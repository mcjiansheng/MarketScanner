# 手机端用户指南（Mobile User Guide）

> 状态：**当前有效 / IMPLEMENTED / HOST TESTED**（真机流畅度和完整扫描仍需 DEVICE SMOKE）。最后核对：2026-08-13。

## 首页

首页大型“新建扫描”和菜单中的“开始门店扫描”都先进入同一个轻量地图选择页；用户可选择已有地图或导入新地图，确认后才加载该地图并进入全手机扫描配置。“门店地图”管理同一个地图库；“处理历史扫描”和“历史结果”负责结束后的手机处理与查看。自由扫描建图、原始数据录制和旧 PC 预处理兼容入口位于“实验与兼容工具”，不再作为主流程。

## 第一次使用

门店地图 → `+` → 选择“导入 XLSX / CSV / JSON”或“导入已有 PC 地图包”。

- 文件尚未选择时不显示 0% 或空进度条。用户选定文件并开始安全复制后，页面才显示百分比、进度和用时，再依次显示解析、业务身份、楼层、道路图、逐层距离场、空间索引、预览、manifest、自验证、提交和注册等真实阶段。
- 完成页显示地图名、门店 ID、`prior_map_id`、package SHA、canonical SHA、楼层数、有效/忽略元素、警告和源文件信息。不能只以“导入成功”代替这些结果。
- 正式 PC v2 地图包会按原字节复制、production integrity 复验并注册到同一个地图库；缺 `store_id`、canonical identity 或内容完整性不合格的旧包必须重新生成，不能进入扫描。
- 地图列表显示后会在空闲时预热一次导入菜单和系统文件选择器，因此首次点击“导入新地图”与“导入 XLSX / CSV / JSON”不应再承担明显的一次性初始化；此时不会读取文件或开始编译。

## 扫描

开始门店扫描 → 在轻量列表选择已有地图或导入新地图 → 确认地图并等待单次加载 → 选择楼层 → 在预览图上点击起点 → 调整位置与朝向 → 开始扫描 → 扫描价签 → 结束扫描。

- 地图支持 1×—8× 捏合缩放、单指平移、双击放大/复位和点击选点。
- 起点可用上/下/左/右方向键微调，步长可选 0.1 m、0.5 m 或 1.0 m。
- 朝向使用东 0°、北 90°、西 180°、南 270°以及左转/右转 15°，不使用横向滑杆。
- 地图选择页左上角显示“关闭”；配置页使用系统返回按钮和返回手势。配置页不再提供地图 picker，需要换图时返回轻量列表；离开配置页会取消尚未完成的启动，不会让扫描在后台自行开始。
- 第一次使用相机时，App 会先完成系统权限请求；授权后重新执行完整的地图/身份/权限检查，再提交启动。拒绝权限时保持在配置页并提供“打开设置”。
- 普通 `RTABMapApp` scheme 的默认 Run 已改为 Release，会执行严格 build identity 生成与验证；从已提交且 tracked tree 干净的版本直接 Run 即可测试扫描。`RTABMapApp-QualifiedDevice` 仍可使用。Test/Analyze 或手动 Debug 配置仍没有正式身份，只用于导入和 UI 调试。

点击开始后，地图匹配器、会话目录、连续 SQLite 数据库和 sidecar writer 在后台准备。只有相机、RTAB-Map 录制、receipt 和 workflow context 都成功后才进入扫描；失败或取消会自动停止并回滚，不会留下没有结果记录的后台扫描。

用户不输入坐标数值、矩阵、RTAB-Map node、JSON 或因子权重。

扫描价签时使用固定框对准一个条码。相机持续自动对焦，Vision 最多 10 Hz；贴近导致条码略超框时会自动对同一帧尝试一次扩展范围。候选连续 2 帧锁定，通常采集 4 帧、最低 3 帧、最长 4 秒。若完整证据和 exact-node-local 可重算位置已经保存，但定位、深度或货架关联质量不足，应用会提示“低置信度已保存”，无需立即重复扫描。少于 3 帧可重算位置或 burst/exact node/node-local point 等权威证据不足，或输入属于历史 v1 coordinate frame 时，条码仍以 `LOW_CONFIDENCE` 和空坐标保留，同时生成独立补扫建议；只有身份串包、必需写入失败等无法安全界定或提交的会话级错误才终止。

## 扫描结束

结束扫描 → 安全保存 → 自动处理 → 快速图优化 →（必要时一次现有全图优化）→ 最终轨迹 →
价签最终定位 → 自动质量门 → 生成工作簿

处理原则是“能读出的结果必须保留，可靠性另行标记”：少量价签帧缺失、个别价签坏记录、个别人工校准未绑定到最终最近节点、图质量未通过，或没有 publish-eligible 节点，都不再让整份结果消失。App 会生成不可变的部分结果，并显示 `PARTIAL_REVIEW_REQUIRED` 或 `LOCAL_FRAME_ONLY`、保留的坐标数/价签数、降级原因和“不可直接发布”。

- 有已选择起点时，非发布轨迹可按起点对齐到原始地图，坐标仍会标为 `DEGRADED_MAP_ALIGNED`，供人工复核。
- 无法安全对齐地图时，手机本地坐标保存在专用 `local_*` 列，绝不伪装成地图坐标。
- 少量 burst/observation 不完整时，条码仍保留在 PriceTags；可由至少 3 帧重算位置则保留低置信度位置，否则保留空坐标。两者的价签主结果都标为 `LOW_CONFIDENCE`；`RESCAN_REQUIRED` 只出现在独立补扫任务中。
- 真正没有任何有限轨迹节点时才生成 `RESCAN_SESSION`；数据库/身份/必要文件/输出写盘损坏、用户取消和资源不足等无法安全继续的故障仍会终止。

## 结果页

结果质量：`COMPLETE / PARTIAL_REVIEW_REQUIRED / LOCAL_FRAME_ONLY`；是否允许发布；自动通过/低置信度/需要补扫价签数；坐标总行数、有效/降级/不可用秒数；处理耗时；结果地图预览。
操作：[导出 XLSX] [查看补扫任务] [查看诊断摘要]

最终业务结果在同一 Result 目录中：

- `final_trajectory.jsonl`，以及 XLSX 的 `DevicePositions`：相对于原始先验地图的每秒手机坐标、朝向、本地时间、UTC、置信度和状态；若仅有本地诊断坐标则明确写入 `local_*`。
- `final_tags.json`，以及 XLSX 的 `PriceTags`：所有保留下来的条码、地图位置、`shelf_code`、唯一物理 `shelf_segment_id`、front/back、沿货架距离、位置比例和质量原因。
- `quality_report.json` / `RunSummary`：为什么完整、为什么降级、是否允许发布。
- `rescan_tasks.json` / `RescanRequired`：只列需要补扫/复核的局部任务。

历史结果若校验失败会从正常列表隔离到审计 quarantine，并在诊断中显示；App 不会把损坏结果当作成功结果，也不会自动删除原 payload。

## 无 PC

从原始地图到工作簿的最终用户流程可以完全不使用 PC。导入正式 PC v2 地图包只是同一地图库支持的兼容来源，不会创建第二套配置页、启动逻辑或扫描系统。
