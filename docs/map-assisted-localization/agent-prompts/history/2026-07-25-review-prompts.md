## 0. 通用审查原则

审查必须检查四类一致性：

```text
需求 ↔ 代码
代码 ↔ 测试
代码 ↔ 文档
文档 ↔ Git 历史
```

不得只阅读实现 Agent 的总结。必须直接检查：

- Git diff 和提交；
- 实际代码路径；
- schema；
- 测试内容；
- 测试输出；
- UI 状态；
- 原始数据库不可变性；
- 自由扫描模式回归；
- 文档是否超前。

问题分级：

```text
BLOCKER  数据损坏、安全、旧流程破坏、无法运行、错误结果被标记为成功
HIGH     可能产生错误跨通道定位、错误货架绑定、文档严重不一致
MEDIUM   边界情况、性能、可恢复性、UI 易用性不足
LOW      清晰度、重复代码、小范围可维护性
```

审查流程：

1. Pass A：只读审计，不修改文件；
2. 将结果写入 `docs/map-assisted-localization/STAGE_<N>_REVIEW.md`；
3. 若发现 BLOCKER/HIGH 且修复明确，可在单独 `fix(...)` 提交中修复；
4. 修复后重新运行相关测试和全量回归；
5. 更新 review 文档，保留原问题、修复和证据；
6. 不扩大阶段范围，不顺手实现下一阶段功能。

每次审查最终必须给出：

```text
APPROVED
APPROVED WITH CONDITIONS
REJECTED
```

# 阶段二独立审查 Prompt

```text
你是独立定位算法、iOS 和安全 Review Agent。请审查 MarketScanner 的“阶段二：实时地图匹配、定位置信度与二维码价签测量”。

开始前：
- 确认阶段一 review 为 APPROVED 或条件已满足；
- 检查阶段二提交范围；
- 运行阶段一全量回归；
- Pass A 先只读审查。

一、线程与生命周期

检查：
- ARFrame delegate 不同步执行重型匹配；
- 后台任务有取消和代际 token，旧结果不会覆盖新 session；
- 开始、暂停、中断、恢复、结束的状态机正确；
- 任务不会在数据库关闭后继续访问过期对象；
- 缓存、点数、历史、候选有上限；
- 内存压力和热状态仍生效；
- 自由扫描模式不加载不必要的 prior map localizer。

二、深度结构提取

检查数学和实现：
- 相机内参和坐标变换；
- sceneDepth 对齐；
- 无效深度过滤；
- 地面/天花板过滤；
- 高度范围；
- 点数上限；
- 动态障碍鲁棒性；
- orientation/viewport 处理；
- 测试是否包含非单位相机变换和旋转姿态。

三、扫描匹配

验证：
- 距离场单位、分辨率、原点、边界正确；
- 搜索围绕 ARKit 预测；
- 鲁棒损失真实参与评分；
- 最佳/次佳唯一性被计算和使用；
- Top-K 候选真实保留；
- 道路图是软约束；
- 大修正门控；
- 连续性门控；
- 地图不匹配不会强拉；
- 接受/拒绝日志完整；
- T_map_from_arkit 更新方向和矩阵乘法顺序正确；
- 不重置 ARKit 世界坐标；
- 不修改原始 DB。

构造或运行以下测试：
- 两条几乎相同平行通道；
- 重复货架周期；
- 交叉口消歧；
- 柱子消歧；
- 大量动态离群点；
- 真实结构与地图缺一段；
- 错误初始朝向；
- tracking 中断后恢复；
- 错误高分候选；
- 候选分数接近。

审查重点是避免“看起来平滑但匹配到错误通道”的灾难性错误。

四、置信度和状态

验证 stable/usable/weak/lost：
- 阈值集中定义；
- 状态存在滞回，避免频繁闪烁；
- 置信度不是只由单一 score 决定；
- 有效点数、唯一性、连续性、tracking 状态被考虑；
- UI 和数据日志使用同一状态源；
- weak/lost 时自动价签提交被正确限制；
- 人工校准可审计。

五、二维码识别

检查：
- 使用 ARFrame capturedImage；
- 不启动第二相机；
- 识别频率有界；
- 结果与正确帧时间戳绑定；
- 旋转和图像坐标变换正确；
- 重复码去重不会丢失相隔较久的合法重复扫描；
- 不启用 NFC。

六、价签测量

逐步验证：
- 码框角点；
- 深度采样；
- 中位数；
- 反投影；
- 相机到 ARKit；
- ARKit 到先验地图；
- 高度；
- 货架平面求交 fallback；
- 原始和吸附位置都保存。

必须有测试证明：
- 手机离货架 1 m 时，标签不会被记录在手机位置；
- 无深度时不会伪造高置信结果；
- 错误深度离群点被拒绝；
- 图像时间和 pose 时间不匹配时有门控；
- 坐标轴和相机朝向变化正确。

七、货架关联

测试：
- 同侧最近货架；
- 对面货架；
- 相邻货架端点；
- 货架背面；
- 隔着另一个货架；
- 两候选分数接近；
- 旋转货架；
- 不规则柜台；
- 价签超出货架范围。

检查最终记录包含 shelfCode、rowFlag、crossCode、side、offset、height 和各类 confidence。

八、UI 可用性

实际走查：
- 非专业用户可以选择地图、起点、开始；
- stable/weak/lost 文案清晰；
- 地图角色和朝向清晰；
- 扫描价签是主按钮；
- 低置信结果要求确认；
- 丢失时可人工重定位；
- 暂停/结束不会丢数据；
- 高级诊断默认折叠；
- 自由扫描 UI 不回归。

九、模拟指标

重新运行阶段二指标，不仅使用实现 Agent 给出的结果。检查测试数据是否过于简单或与算法同源导致自证。

至少报告：
- median/p95 位置误差；
- p95 朝向误差；
- 通道准确率；
- 灾难性跳转次数；
- 标签货架关联率；
- recovery 时间；
- 匹配耗时 p50/p95；
- 内存和 sidecar 增长。

十、办公室干跑

检查证据：
- ARKit 未被扫码中断；
- 直行和转弯；
- 低置信度提示；
- 人工校准；
- 至少若干二维码；
- 结束后数据完整；
- 不能把此结果表述为超市精度验收。

十一、文档和 Git

确认算法、阈值、限制、数据格式、UI 和测试与代码一致。任何实验性功能必须标记实验性。

十二、输出

创建并提交：
`docs/map-assisted-localization/STAGE_2_REVIEW.md`

给出 APPROVED / APPROVED WITH CONDITIONS / REJECTED，并列出进入阶段三前必须解决的问题。

BLOCKER 示例：
- 可能静默跨通道跳转；
- weak/lost 仍自动确认价签；
- 扫码启动第二相机；
- 标签位置等于手机位置；
- 原始 DB 被改写；
- 自由扫描无法正常使用。
```
