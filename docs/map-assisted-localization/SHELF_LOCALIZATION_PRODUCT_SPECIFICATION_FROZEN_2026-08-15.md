## 0. 本文档解决什么问题

设计评审文档列出的 P1-B～P1-E 与 P2 此前被判定为"存在无法确定项"：验收真值缺失、平行通道多解的产品行为未定、穿架模型参数未定、闭环确认阈值未定。2026-08-15 产品侧给出了明确决策，这些"无法确定项"中的绝大部分已被冻结为具体规格。本文将其固化为实施依据，并明确：

1. 每项冻结规格的内容、来源和推导出的系统行为；
2. 由此简化的实现路线（哪些设计文档中的复杂机制被砍掉或降级）；

4. 替代设计文档 §13.3 的验收标准。

**凡与本文冲突的旧文档表述（尤其是设计文档 §13.3 的绝对精度指标、人体胶囊体模型、严格多解发布门），以本文为准。**

## 2. S-1 地图权威性

### 规格
产品保证输入的先验地图（门店 XLSX → 编译包）中货架位置、尺寸、通道开口与现场一致。地图几何因此可作为**硬约束**参与定位与穿架检测。

### 推导出的系统行为
1. 穿架检测使用零地图容差 + 手机前伸限量（S-7），不再需要 `ε_map` 软容差带分层；
2. 地图编译产物的身份（canonical SHA / package SHA）继续全链绑定，任何处理必须核对；
3. 设计文档 P2 中的 `map_mismatch` 正式降级路径**不再作为发布阻断项**：当观测长期与地图冲突时，系统仍记录诊断并降低定位置信度，但不需要实现完整的"地图错了还是定位错了"仲裁逻辑。若现场确实出现货架移动，按低置信处理并依赖人工重定位（S-8）。

### 边界声明
该保证是产品侧承诺。系统侧仍保留"观测-地图冲突计数"诊断输出，用于事后发现承诺被打破的情况；冲突计数本身不阻断扫描。

## 3. S-2 / S-3 / S-12 位姿输入容差

### 规格
- 用户在配置页选择的起始位姿：允许与真实位姿相差 1–3 m、15°；
- 扫描中"重新选择位置"（人工重定位）：同样允许 1–3 m、15° 的输入误差；
- 该误差由定位器通过后续结构匹配与闭环平滑吸收。

### 推导出的系统行为
1. 定位器初始协方差与人工锚点融合不确定度统一取 **3 m / 15°**（S-12）：现有代码人工锚点为 3 m / 20°，实现 P1-B/E 时收紧朝向项；
2. 配置页与重选位交互的提示文案（现行"允许 3–5 m 和 20–30° 误差"）应更新为与本规格一致；
3. 结构匹配收敛判据必须以"3 m / 15° 初值可在有限帧内收敛"为设计目标（现行 0.25 m 单次修正上限 + fresh-support 门已满足，不需放宽）。

## 4. S-4 / S-5 / S-6 价签输出规格

### 规格
最终输出的每个价签：
1. **必须绑定具体货架**（`shelf_segment_id` + side）；不能绑定的价签不得出现在发布成果中（保留为待复核记录，沿用现行 `UNASSOCIATED` 语义）；
2. 绑定后的平面坐标误差允许**直径 1 m**（工程实现为：价签点到其绑定货架面的法向残差 ≤ 0.5 m，且沿架投影点位于该货架段轴向范围内）；
3. 高度坐标不作要求：`measurement_height_m` 维持现状——业务展示字段，不进入权威坐标传播，不参与验收。

### 推导出的系统行为
1. **发布判据重写**（替代设计文档 §13.3 的绝对精度指标）：
   ```text
   价签可发布
   iff 绑定货架身份唯一（或两侧观测一致确认）
     AND 法向残差 ≤ 0.5 m
     AND 沿架投影在货架段范围内
     AND 坐标传播链为 node-local v2（P0 已满足）
     AND P1-A publication invariant 全部通过
   ```
2. "投影到货架线"不再被禁止——设计文档 §11 担心"用投影自洽冒充精度"，但本规格下**投影本身就是产品合同**（价签必须落在货架上，容差 1 m）；仍需同时保留 raw/optimized/projected 三类点与投影残差，供复核；
3. 该规格使**无外部真值的合格判定成为可能**：价签贴架残差、两侧观测一致性、回环残差均为自洽指标（见 §8）。

### 明确放弃的要求
- 设计文档 §13.3 中 "accepted tag 二维真值误差 P95 ≤ 0.40 m"、"沿架 offset P95 ≤ 0.30 m" 等**基于外部真值的绝对精度指标不再作为发布门**；
- 若未来产品需要绝对精度声明，须另行安排控制点真值并单独立项。

## 5. S-7 / S-8 穿架模型与通道身份决策

### 5.1 穿架模型（S-7）
- 轨迹主体 = 手机位姿点（非人体）；
- 允许该点进入货架多边形内部 ≤ **0.4 m**（`o_phone`，覆盖扫价签时的手臂前伸）；
- 判定规则：
  1. 节点侵入：节点 2D 位置深入货架面 > 0.4 m → 判穿架；
  2. 线段穿架：相邻节点间的扫掠线段穿越货架且进入深度 > 0.4 m → 判穿架（稀疏节点跳变防护，设计文档 §4.5 保留项）；
- **人体胶囊体、`r_body`、`ε_map` 软容差带全部不实现**（设计文档 §9.1 相关内容砍掉）；
- 手机端穿架检测用于候选淘汰（实时），PC 端用于轨迹审计（现行 `corridor_route_matcher` 的点侵入/线段穿架检查保留，容差值改为 0.4 m）。

### 5.2 通道身份决策（S-8）—— best-candidate commit + 人工兜底

产品判断：通道间距达数米，从已闭环区域转移到新区域的位移也只有数米，正常工况下累计误差远小于半个通道间距，候选天然唯一；即使出现错误，已有"手动调整位置"组件（`bb09e13` 加固的人工重定位链）可纠正。

据此冻结的行为：

1. **始终提交得分最高的单一候选**作为当前通道/货架身份，不做"多解时冻结输出"的保守路径；
2. **低置信标记而非阻塞**：当触发 C-2 阈值（候选分差小、或长时间无可靠闭环）时，在扫描 HUD 与质量报告中标记"定位置信度低，建议核对位置"，但扫描与坐标写入不中断；
3. **人工重定位是最终兜底**：用户可随时用现有"重新选择位置"纠正整段 gauge（bounded correction field 沿轨迹连续传播，现行能力）；
4. **前提条件（必须实现）**：闭环质量实时可见。系统须在以下情况主动触发低置信提示，否则 S-8 的前提不成立：
   - 可靠回环连续失败超过 C-2 距离阈值（山姆现场曾出现绕货架闭环失败案例，见 `SAM_SCAN_REPORT_2026-08-02.md` 与测试者反馈 S3）；
   - 在线修正量异常（接近 0.25 m 单次上限的频率突增）；
   - tracking 质量降级（lost/recovery 频次）。

### 5.3 由此简化的实现
设计文档 §9.2 的资源有界 Top-K/beam 混合滤波器**降级为内部实现细节**：
- 仍可在内部维护少量候选用于打分与分差计算，但**不需要**把多解作为产品状态对外暴露；
- 不需要"通道待确认"阻塞式 UI（只保留低置信提示条）；
- 状态机从设计文档的 8 态简化为：`BOOTSTRAP → TRACKING → LOW_CONFIDENCE ⇄ TRACKING`（闭环/两侧观测证据充足时恢复 TRACKING）。

## 6. S-9 货架闭环判据：两侧观测一致性

### 6.1 产品描述的场景（原文转写）

```text
在通道 N 行走时，同时扫到左手边和右手边的货架；
离开通道右转后，扫描的是之前在右手边的那排货架（现在是新通道的一侧）；
进入通道 N+1 后，左手边的货架 == 之前通道 N 右手边的货架；
最终同一货架获得两段（两侧）观测，构成完整货架闭环。
```

### 6.2 系统实现定义

**货架闭环 = 同一 `shelf_segment_id` 的两个独立观测窗口分别来自货架两侧，且相互印证。**

确认条件（全部满足才可升级为正式货架闭环证据）：

1. 两个观测窗口的 exact node 区间可读、属于同一 graph component、pose epoch 一致或有正式 bridge（依赖 P1-B 合同）；
2. 两侧判定：两个窗口的观测法向近似相反（夹角 > 120°），即确为货架两侧而非同侧重访；
3. phone↔shelf 相对 SE(2) 在两个窗口中一致，差异在 C-1 阈值内；
4. 几何吻合：深度结构点到货架面/端头的残差分布在阈值内，且 inlier 比例 ≥ C-1 下限；
5. 无主导动态遮挡证据（C-3 标定的静态判定之外的运动体剔除）。

通过后产出（写入 `shelf_loop_events` sidecar，进 manifest）：
- 确认的 `shelf_segment_id` + side ×2；
- 两窗口 exact node 区间与时间；
- phone↔shelf 相对 SE(2)（以确认后优化值为准）；
- 吻合统计（inlier 比、残差中位数/最大值）；
- 该证据允许：a) 把相关 RTAB-Map 回环提升为具体货架回环因子；b) 对整圈轨迹做回溯平滑（不许瞬移）。

### 6.3 与"候选/明显"的对应关系

- **候选**：当前观测能与地图上说通的若干货架（每个候选带得分）；
- **明显/margin**：第一与第二候选的分差。本规格下 margin 的**免真值判据**就是 §6.2 的两侧观测一致性：同一货架获得两侧一致观测时，错误候选（隔壁平行货架）无法同时满足两侧一致性，margin 自动拉开；
- 若始终只有单侧观测且 C-2 分差不足：按 S-8 提交最优候选 + 低置信标记，等待走到端头/下一通道后由两侧观测追认或纠正。

## 7. S-10 资格策略（替代逐店真值）

### 规格
1. **不要求每家门店提供真值数据**；
2. 一次性代表门店真值采集为**可选**：若执行，仅用于验证算法本身（阈值标定参考），不作为任何门店的发布前提；
3. 例行资格 = **自洽性指标**，全部可从扫描自身证据计算：

| 指标 | 合格线（冻结） | 来源 |
| --- | --- | --- |
| 可靠回环残差中位数 | ≤ 0.3 m（现行图优化门内已有等价检查） | RTAB-Map loop residual |
| 已接受轨迹的货架点侵入 / 线段穿架（>0.4 m） | 0 | S-7 审计 |
| 两侧观测一致性确认的货架，相对位姿差异 | ≤ C-1 阈值 | S-9 |
| 发布价签的贴架法向残差 | ≤ 0.5 m | S-5 |
| 未绑定/低置信/重扫价签进入发布成果 | 0 | P1-A invariant |
| 人工重定位后残差收敛 | 修正场梯度 ≤ 现行门（平移 0.176 m/m 级） | bounded correction field |

4. 发布结论的允许表述为：**"内部一致且满足冻结容差"**；禁止表述为"绝对精度已验证"。

## 8. 对实现路线的影响（P1-B → E / P2）

### P1-B（证据合同）——无外部依赖，可立即开工
- 内容不变：epoch/component 逐记录身份、`corridor_hypotheses` / `shelf_observation_windows` / `shelf_loop_events` sidecar、manifest v5 + hash tree；
- 本文新增要求：`shelf_observation_windows` 必须记录**观测侧（left/right）**与法向，以支撑 §6 两侧判定；
- 旧会话兼容：合同 v2/v1 会话按"无货架证据"处理，不阻断既有处理链。

### P1-C（手机通道/货架状态机）——按 §5 大幅简化
- 单最优候选提交 + 低置信标记 + 人工兜底；不实现阻塞式多解 UI；
- 穿架检测用点 + 0.4 m 限量 + 扫掠线段；
- **前置条件**：真机性能摸底（每帧候选打分 + 深度残差的耗时与热预算）。性能不达标时降级策略：降低候选打分频率（复用现行 1–2 Hz 自适应定位节拍），不降低穿架检测频率。

### P1-D（PC 混合图正式化）
- 放行路径明确：corridor/free-space 结果满足 §7 自洽指标 + S-5 贴架判据即可进入正式发布，删除"成功即 `published_capable=false`"死规则；
- 因子集合按本文简化：保留 relative/loop/manual-anchor/free-space(0.4 m)/shelf-face 因子；**人体胶囊、corridor hinge、switch variable 不实现**；
- 沿轴不可观问题按设计文档处理：沿轴 covariance 如实增长，由端头/两侧观测闭环/人工锚点校准，不伪造小不确定度。

### P1-E（具体货架闭环）
- 直接按 §6 实现；升级条件 8 条中的"冻结 margin 策略"由 C-1 标定值承担；
- 闭环确认后回溯平滑整圈轨迹（复用 PC 因子图，手机端不瞬移）。
