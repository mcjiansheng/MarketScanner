# 超市分段扫描与外部存储说明

本文说明 iOS 超市扫描原型中的分段保存策略，重点是如何在大型超市场景中减少 iPhone 本机存储占用，并将扫描分段导出到用户选择的外部存储设备。

## 目标

大型超市连续扫描会产生较大的 RTAB-Map 数据库、点云和辅助记录。如果所有数据都长期保留在 App 本地 Documents 目录中，容易占满手机存储。

当前实现采用稳定优先的两阶段保存策略：

```text
当前分段采集
  -> RTAB-Map 原生数据库先保存到 App 本地沙盒
  -> 写出 metadata.json / price_tags.json / price_tags.csv
  -> 如果用户选择了外部保存位置，复制整个 segment 到外部目录
  -> 校验外部副本
  -> 校验成功后删除本地 segment 副本
  -> 打开新的临时数据库，继续扫描下一段
```

这样避免 RTAB-Map 原生 C++ 层直接写入 iOS 文件提供器或外接盘路径导致崩溃，同时又能在外部导出成功后释放本地 segment 占用。

## 用户操作

1. 打开 App 菜单。
2. 进入 `设置 -> 超市扫描设置`。
3. 根据现场需要调整自动分段阈值：
   - 扫描面积阈值 m2
   - 数据库阈值 MB
   - 内存阈值 MB
   - 分段前最少节点数
4. 点击 `选择保存位置`，在 iOS 文件选择器中选择本地文件夹或外接存储设备目录。
5. 开始扫描。
6. 系统达到阈值时自动保存分段，或用户点击 `保存当前分段` 手动保存。

如果用户没有选择保存位置，系统使用默认 App Documents 目录，并保留本地 segment。

## 输出目录结构

每次扫描会话会创建一个目录：

```text
SupermarketSession-YYYYMMDD-HHMMSS/
  segment_0001/
    rtabmap_segment_0001.db
    metadata.json
    price_tags.json
    price_tags.csv
  segment_0002/
    rtabmap_segment_0002.db
    metadata.json
    price_tags.json
    price_tags.csv
```

如果选择了外部保存位置，外部目录中会生成同样的 `SupermarketSession-...` 目录。复制成功并校验通过后，本地 `segment_000x` 会被删除，继续扫描时只保留当前正在使用的临时数据库和后续分段所需的运行数据。

## 自动分段触发条件

当前分段满足以下任一条件时会自动保存：

```text
估算扫描面积 >= 用户设置的面积阈值
RTAB-Map 数据库内存 >= 用户设置的数据库阈值
App 已用内存 >= 用户设置的内存阈值
```

同时需要当前分段节点数达到“分段前最少节点数”，避免刚开始扫描时过早切分。

## 失败保护

为了避免数据丢失，删除本地 segment 前会先做外部副本校验。校验内容包括：

```text
外部副本文件数量 == 本地副本文件数量
外部副本总字节数 == 本地副本总字节数
```

处理结果如下：

```text
外部复制成功且校验成功
  -> 删除本地 segment 副本

外部复制失败
  -> 保留本地 segment 副本
  -> 显示中文提示

外部校验失败
  -> 保留本地 segment 副本
  -> 显示中文提示

外部复制成功但本地删除失败
  -> 外部副本保留
  -> 本地副本也保留
  -> 显示中文提示
```

## 为什么不直接写外部存储

RTAB-Map 数据库保存由原生 C++ 层执行。iOS 的外接盘、文件提供器和安全作用域路径对原生层并不总是透明，直接把数据库路径交给原生保存可能触发运行时 abort。

因此当前实现让原生层只写 App 自己的沙盒目录，再由 Swift 的 `FileManager` 负责复制到用户选择的位置。这样更符合 iOS 文件访问模型，也更容易在失败时给用户明确提示。

## 注意事项

- 本地仍需要容纳“当前正在保存的单个 segment”的临时空间。
- 外部设备拔出、权限变化或空间不足时，系统会保留本地副本。
- 复制和清理发生在每次分段保存时，分段阈值越小，本地峰值存储越可控，但保存次数会更多。
- 用户更换保存位置后，新的分段会复制到新的位置；已成功导出的旧分段不会自动迁移。
