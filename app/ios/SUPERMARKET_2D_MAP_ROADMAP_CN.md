# 大型超市扫描结果生成二维平面地图技术路线

本文面向当前 iOS 超市分段扫描原型，说明如何基于已经保存并合并的 RTAB-Map 扫描结果，生成可用于业务系统、巡检、货架定位和人工校正的二维平面地图。

当前项目已经完成了通过分段记录和合并支持大型区域扫描。下一阶段的重点不是继续依赖原生粗糙地图输出，而是建立一条更可控的二维地图生成链路：从多段扫描数据库和点云中提取稳定的平面结构，修正大区域累计误差，生成带质量指标和可编辑语义层的平面地图。

## 目标

生成的二维地图应满足以下目标：

- 只表达单层地面的水平平面结构，暂不处理多层楼、楼梯、斜坡和垂直高度变化。
- 以俯视二维坐标系表达墙体、货架、通道、障碍物、可通行区域、价签位置和扫描轨迹。
- 能处理多段扫描合并后的局部错位、漂移、旋转误差和尺度误差。
- 输出结果应稳定、可复现、可检查，并允许人工或半自动校正。
- 保留每个地图元素的置信度、来源 segment、时间、节点范围和生成参数，便于追踪问题。
- 不强依赖 RTAB-Map 原生二维地图结果，只把 RTAB-Map 作为数据来源和初始位姿来源。

## 非目标

当前阶段不处理以下问题：

- 多楼层地图、楼层切换和跨楼层定位。
- 高精度三维重建、货架层板高度分析、商品级三维建模。
- 完全自动理解所有业务语义，例如自动识别所有货架品类和商品陈列。
- 在手机端完成所有重计算。大型地图的重建、全局优化和矢量化可先放在离线工具或桌面端完成。
- 替代 RTAB-Map 的定位和建图主流程。当前方案是在扫描结果之后做后处理和地图产品化。

## 输入数据

建议把二维地图生成视为一个独立的后处理任务，输入包含以下内容：

```text
SupermarketSession-YYYYMMDD-HHMMSS/
  segment_0001/
    rtabmap_segment_0001.db
    metadata.json
    price_tags.json
    price_tags.csv
  segment_0002/
    rtabmap_segment_0002.db
    metadata.json
    price_tags.json
    price_tags.csv
  ...
  SupermarketMerged-YYMMDD-HHMMSS.db
```

其中每个 segment db 提供：

- 关键帧节点。
- 节点位姿。
- RGB 图像、深度、LiDAR 或点云数据。
- 回环、邻接边和优化后的图结构。
- RTAB-Map 内部网格或局部地图数据，如果存在。

sidecar 文件提供：

- segment 序号、扫描面积、节点数、数据库大小、内存情况。
- 价签记录和扫描时位姿。
- 用户选择的导出位置和分段保存过程信息。

后续建议补充的输入：

- segment 开始和结束节点 ID。
- segment 与 segment 之间的连接关系。
- 保存时的设备姿态质量、跟踪状态、低内存警告、ARKit tracking state。
- 人工锚点，例如入口、收银台、柱子、固定货架端点。
- 已知平面尺寸或简单 CAD 参考图，如果现场可以提供。

## 输出数据

二维地图不建议只输出一张图片，而应输出一组分层数据。

```text
Map2D-YYYYMMDD-HHMMSS/
  map.json
  occupancy_grid.png
  occupancy_grid.yaml
  vector_map.geojson
  semantic_layers.json
  price_tags.geojson
  trajectory.geojson
  quality_report.json
  preview.png
```

各文件职责如下：

- `occupancy_grid.png`：二维占据栅格，表达墙体、货架、障碍物和未知区域。
- `occupancy_grid.yaml`：分辨率、原点、坐标系、图片尺寸等元信息。
- `vector_map.geojson`：矢量化墙线、货架边界、通道边界和区域多边形。
- `semantic_layers.json`：业务语义层，例如货架区、通道区、入口区、收银区、冷柜区。
- `price_tags.geojson`：价签位置点，保留原始 payload、segment、节点和置信度。
- `trajectory.geojson`：扫描轨迹、分段边界、异常漂移位置。
- `quality_report.json`：地图质量、闭环质量、段间误差、覆盖率、人工待确认项。
- `preview.png`：用于 App 或后台快速浏览的渲染图。

## 总体技术路线

推荐采用“原始数据提取 -> 位姿和段间校正 -> 平面投影 -> 占据融合 -> 结构化矢量化 -> 语义挂接 -> 质量检查 -> 人工校正”的流水线。

```text
分段数据库 / 合并数据库
  -> 读取节点、位姿、点云、价签
  -> 检查每段质量和段间重叠
  -> 做全局位姿图校正
  -> 将三维点云投影到二维地面坐标
  -> 生成多层占据证据
  -> 融合为二维占据栅格
  -> 提取墙体、货架、通道等结构
  -> 绑定价签和扫描轨迹
  -> 输出矢量地图、栅格图和质量报告
```

这条链路中，RTAB-Map 的输出只作为初始估计。最终二维地图应由我们自己的后处理模块控制生成逻辑、参数、质量阈值和可解释输出。

## 坐标系约定

当前阶段建议采用一个简单稳定的平面坐标系：

- 地图坐标系为 `map_2d`。
- X/Y 表示地面平面坐标。
- Z 只用于过滤点云高度，不参与最终二维地图表达。
- 原点可取第一段第一个有效节点，或人工指定入口点。
- 所有 segment 的点云和价签先转换到统一 `map_2d` 坐标系，再做投影和融合。

在 iOS/ARKit/RTAB-Map 中，常见的坐标轴约定可能不一致。需要在导出时固定转换规则，并写入 `map.json`：

```text
rtabmap pose -> project coordinate transform -> map_2d coordinate
```

如果后续发现地图整体旋转 90 度、镜像或朝向不符合业务使用，可以只调整最终 `map_2d` 输出转换，不修改原始扫描数据。

## 高度过滤策略

虽然当前不考虑纵向高度变化，但点云中仍包含地面、货架、墙体、天花板、人体、购物车、临时物体等高度差异。二维地图不能简单把所有点投影到地面，否则会引入大量噪声。

建议先做高度分层：

- 地面层：接近地面，主要用于估计可通行区域。
- 低障碍层：购物车、低货架底部、临时物品，容易变化，置信度较低。
- 主结构层：货架、墙体、冷柜、柱子等稳定结构，是二维地图的主要依据。
- 高层噪声：天花板、灯具、上层货架、反光结构，通常不进入二维占据图。

初始高度范围可按设备坐标和现场情况调参，例如：

```text
地面层：-0.2 m 到 0.2 m
主结构层：0.3 m 到 2.2 m
高层过滤：高于 2.5 m 的点默认忽略
```

这些阈值不应写死，应作为地图生成参数保存。大型超市中地面可能有轻微坡度或 ARKit 坐标漂移，因此高度过滤要允许按局部轨迹估计地面，而不是只依赖全局固定 Z。

## 平面投影与占据证据

二维地图生成的核心是把三维观测转成二维占据概率。

每个关键帧可贡献两类证据：

- 命中证据：点云落到某个二维栅格，说明这里可能有障碍物或结构。
- 空闲证据：传感器到命中点之间的射线经过区域，说明这里大概率可通行或无遮挡。

只使用命中点会让地图变厚、噪声多、通道边界不清晰；只使用轨迹缓冲区会丢失货架和墙体边界。因此需要结合射线清空和点云命中。

建议使用概率占据栅格：

```text
每个栅格保存：
  occupied_score
  free_score
  observation_count
  source_segments
  last_observed_time
  height_band_votes
```

最终分类：

- `occupied`：稳定结构或障碍物。
- `free`：稳定可通行区域。
- `unknown`：未扫描或证据不足区域。
- `conflict`：既有强 occupied 又有强 free，通常代表误差、动态物体或段间错位。

大型超市推荐初始分辨率：

- 预览图：10 cm/pixel。
- 可编辑地图：5 cm/pixel。
- 精细结构分析：2 cm 到 3 cm/pixel，但数据量会明显增加。

## 原生地图粗糙问题的解决思路

RTAB-Map 原生输出粗糙，常见原因包括：

- 局部网格参数偏向实时性，而不是最终制图质量。
- 点云噪声、玻璃/金属反光、货架重复纹理导致结构边界不稳定。
- 大地图内存压力高，实时构图为了性能会牺牲细节。
- 多段合并后局部位姿有错位，直接投影会让货架边缘变厚或重影。

解决方法：

- 不直接使用实时地图作为最终成果，只把它作为预览。
- 在后处理阶段重新读取原始关键帧和点云，使用更严格的滤波、投影和融合参数。
- 对点云做体素降采样、离群点去除和高度分层。
- 对占据图做概率融合，而不是简单像素覆盖。
- 对结构边界做线段提取、方向聚类和矢量化。
- 对低置信区域保留为待确认，不强行生成看似完整但错误的墙体或货架。

## 传感器误差和多段合并误差

大型区域扫描中，误差来源主要包括：

- ARKit/视觉惯性里程计累计漂移。
- LiDAR 深度噪声和反光材料误差。
- 货架重复纹理导致错误回环。
- 人流、购物车、临时堆放物导致动态障碍。
- 分段保存和重新打开临时数据库造成段间连接弱。
- 多段合并时仅按原始位姿串接，缺少足够的跨段约束。
- 大型长通道环境缺少独特特征，局部看起来相似。

这些误差在二维地图中通常表现为：

- 同一条货架边界出现两条平行线。
- 通道宽度忽大忽小。
- 闭合走廊无法闭合。
- 价签点偏离货架。
- 合并段交界处有旋转错位。
- 地图整体弯曲或局部拉伸。

## 段间校正策略

分段扫描必须给二维地图生成提供显式的段间校正机制。建议按三个层级处理。

### 第一层：自动重叠检测

在相邻 segment 或可能重叠 segment 之间，检测重叠区域：

- 使用轨迹终点和起点距离判断候选重叠。
- 使用二维投影点云做粗配准。
- 使用货架边线方向和通道结构做结构相似度匹配。
- 使用价签、人工锚点、入口/柱子等稳定点作为强约束。

输出段间候选约束：

```text
segment_i -> segment_j:
  relative_transform
  confidence
  overlap_area
  matched_features
  residual_error
```

### 第二层：位姿图优化

把每个 segment 或每个关键帧作为图节点，建立约束边：

- segment 内部使用 RTAB-Map 优化位姿作为初始边。
- 相邻 segment 添加连续扫描约束。
- 重叠区域添加 ICP/NDT/结构线匹配约束。
- 价签或人工锚点添加点约束。
- 已知墙线、通道方向或 CAD 参考添加弱约束。

优化目标是找到一组二维刚体变换，使整体地图误差最小。

当前阶段推荐先只优化二维自由度：

```text
x, y, yaw
```

不优化 roll、pitch、z，也不做三维非刚性变形。这样更符合“只生成单层二维地图”的目标，也能降低错误优化造成的破坏。

### 第三层：人工可控校正

大型商超很难完全自动生成无误差地图，因此需要设计人工校正入口：

- 手动指定两个 segment 的对应点。
- 手动指定某条货架边界应该对齐。
- 手动锁定入口、收银台、主通道方向。
- 手动删除动态障碍区域。
- 手动标记某些回环为错误约束。

人工校正不应直接修改原始数据，而应保存为 `corrections.json`：

```text
manual_constraints:
  - type: point_pair
    source_segment: 3
    target_segment: 5
    source_xy: [...]
    target_xy: [...]
  - type: line_alignment
    segment: 4
    line_id: shelf_line_12
    target_direction_deg: 90
```

后处理每次重新运行时都读取这些校正约束，保证结果可复现。

## 点云配准方案选择

可以考虑以下配准方法，按复杂度逐步引入。

### 方案 A：二维 ICP

把主结构层点云投影到二维后做 ICP。

优点：

- 实现简单。
- 对相邻 segment 的小错位有效。
- 适合有明显墙体和货架边界的区域。

缺点：

- 对初始位姿敏感。
- 重复货架环境容易配到错误位置。
- 对长直通道的纵向漂移约束弱。

### 方案 B：NDT 或栅格相关匹配

将每段转为二维概率栅格，使用栅格相关性寻找最佳平移和旋转。

优点：

- 对噪声比点到点 ICP 更稳。
- 能直接利用占据概率。
- 适合中等重叠区域。

缺点：

- 搜索空间大时计算慢。
- 重复结构仍可能产生多个局部最优。

### 方案 C：结构线匹配

从二维占据图提取货架边线、墙线和主方向，再匹配线段。

优点：

- 更符合超市场景。
- 能约束货架平行、通道垂直等结构关系。
- 对稀疏点云和局部噪声更稳。

缺点：

- 需要先做好线段提取和置信度评估。
- 货架移动或陈列变化会影响匹配。

### 方案 D：混合约束图优化

综合 ICP、栅格匹配、结构线、价签、人工锚点，统一放入二维位姿图优化。

这是最终推荐方案，但应分阶段实现。不要一开始就做复杂的全自动系统，先建立稳定可解释的基础流水线，再逐步加入更强约束。

## 货架和墙体矢量化

占据栅格适合计算和预览，但业务系统通常需要矢量地图。

矢量化建议步骤：

1. 从占据栅格提取稳定 occupied 区域。
2. 形态学去噪，删除面积过小的动态物体。
3. 使用边缘检测或轮廓提取找到结构边界。
4. 使用 Hough 或 RANSAC 提取长直线。
5. 对相近、平行、共线的线段做合并。
6. 根据通道宽度和货架厚度过滤异常线段。
7. 输出墙线、货架边界、多边形和置信度。

超市具有强烈的人造结构特征，可以利用这些先验：

- 大多数货架边界近似直线。
- 同一区域内货架通常平行排列。
- 主通道与货架方向通常接近垂直或平行。
- 墙体比货架更长、更稳定，通常位于地图外围。
- 冷柜、收银台、入口可能形状特殊，需要单独语义规则。

矢量化时应避免过度美化。宁可输出带置信度的短线段和待确认区域，也不要自动拉直到错误位置。

## 可通行区域生成

二维平面地图除了结构边界，还需要可通行区域。

可通行区域应综合：

- 扫描轨迹缓冲区。
- 射线清空产生的 free 区域。
- 地面层点云连续性。
- occupied 区域膨胀后的避障边界。
- 人工标注的不可通行区域。

建议生成三类区域：

- `walkable_confirmed`：多次观测为空闲，且靠近真实扫描轨迹。
- `walkable_possible`：可能可通行，但观测不足。
- `blocked`：结构或障碍物占据。

不要把没有扫描到的区域自动填成可通行。大型地图中未知区域和可通行区域必须明确区分。

## 价签位置处理

当前系统已经记录价签 ID、payload、segment、节点数和扫描位姿。二维地图中应把价签作为业务语义点。

价签位置可按以下方式处理：

- 初始位置使用读取 NFC 时的设备位姿。
- 如果可获得相机朝向和估计读取距离，将价签位置从设备位置向前投影到最近货架边界。
- 如果无法估计距离，先保存为“设备读取位置”，并标记低置信度。
- 地图生成后，将价签吸附到最近的高置信货架线或货架多边形边缘。
- 如果价签距离最近货架超过阈值，标记为待人工确认。

价签输出应保存：

```text
tag_id
payload
raw_pose_xy
snapped_pose_xy
source_segment
source_node
nearest_shelf_id
confidence
needs_review
```

## 动态物体过滤

超市场景中动态干扰很多，包括顾客、员工、购物车、临时堆头、叉车、打开的纸箱等。二维地图要尽量表达长期稳定结构。

可采用以下策略：

- 单帧或少量帧出现的点降低权重。
- 与扫描轨迹一起移动的近距离点视为动态噪声。
- 低高度、体积小、形状孤立的障碍降低置信度。
- 多个 segment 中重复出现的结构提高置信度。
- 和货架/墙体主方向不一致的小结构默认待确认。
- 人工标记临时区域后，重新生成地图时忽略该区域。

输出质量报告中应列出高冲突区域，便于人工检查。

## 地图质量评估

每次生成地图都应输出质量报告，而不是只输出结果图。

建议指标：

- 总覆盖面积。
- 已知区域、未知区域、可通行区域、占据区域面积。
- segment 数量和每段节点数。
- 段间重叠面积。
- 段间配准残差。
- 闭环约束数量和异常回环数量。
- 占据/free 冲突比例。
- 货架线平均厚度。
- 平行货架方向方差。
- 价签吸附成功率。
- 待人工确认区域数量。

关键告警：

- 某个 segment 与其他 segment 几乎无重叠。
- 合并后同一区域出现明显双线。
- 某段旋转校正超过阈值。
- 价签大量偏离货架。
- 地图中存在大面积 conflict 区域。
- 轨迹自交但没有合理回环约束。

质量报告应支持地图预览中高亮问题区域。

## 人工校正工具设计

为了保证项目能在真实超市落地，建议较早设计一个轻量校正工具。它可以先是桌面端或内部 Web 工具，不必一开始集成到 iOS App。

校正工具应支持：

- 加载 `preview.png`、占据栅格和矢量层。
- 显示每个 segment 的轨迹和颜色。
- 显示段间接缝和冲突区域。
- 手动添加点对点约束。
- 手动旋转/平移单个 segment。
- 手动标记错误回环或错误匹配。
- 手动拉直货架线。
- 手动删除动态障碍。
- 手动确认或调整价签吸附位置。
- 导出 `corrections.json` 并重新运行生成流水线。

人工校正的目标不是让用户画完整地图，而是让用户用少量关键约束修正自动算法难以判断的歧义。

## 推荐模块划分

后处理系统建议拆成以下模块：

### 数据读取模块

职责：

- 读取 segment db 和 merged db。
- 提取节点位姿、点云、图像、局部网格。
- 读取 metadata 和 price tag sidecar。
- 建立统一的数据索引。

输出：

- `ScanDataset`
- `SegmentIndex`
- `FramePose`

- `PriceTagRecord`

### 预处理模块

- 离群点过滤。
- 高度分层。
- 坐标系转换。
- 动态点初步过滤。

输出：

- 按 segment 和 frame 组织的二维投影点。
- 高度层证据。
- 轨迹和观测范围。

### 配准和优化模块

职责：

- 检测 segment 重叠。
- 生成候选相对约束。
- 执行二维位姿图优化。
- 读取并应用人工校正。
- 输出优化后的 segment/frame 位姿。

输出：

- `optimized_poses.json`
- `constraints.json`
- `registration_report.json`

### 占据栅格模块

职责：

- 射线清空。
- 命中点累积。

输出：

### 业务挂接模块

输出：

## 分阶段实施计划

### 阶段 1：离线二维地图最小闭环

目标：先从合并数据库或多个 segment 数据库生成可用的二维占据图。

任务：

- 读取节点位姿和点云。
- 固定高度范围过滤。
- 投影到二维栅格。
- 生成 occupied/free/unknown 三类区域。
- 输出 PNG/YAML/JSON。
- 在预览图中显示扫描轨迹和价签原始位置。

验收标准：

- 对小型超市场景能生成方向正确、比例合理的二维图。
- 货架和墙体大致可辨认。
- 未扫描区域不会被错误填充为可通行。
- 输出中能追踪每个区域来自哪些 segment。

### 阶段 2：分段误差可视化和质量报告

目标：让段间错位和传感器误差变得可见。

任务：

- 不同 segment 使用不同颜色渲染点云投影。
- 检测双线、冲突栅格和异常厚边界。
- 输出段间重叠和残差报告。
- 标记低质量 segment 和疑似错误回环。

验收标准：

- 能在预览图中看出哪些区域由哪个 segment 造成问题。
- 能定位合并误差集中发生的位置。
- 质量报告能给出明确的人工检查列表。

### 阶段 3：二维段间自动校正

目标：降低多段合并导致的错位。

任务：

- 对相邻或重叠 segment 做二维 ICP 或栅格相关匹配。
- 生成段间相对约束。
- 建立二维位姿图优化。
- 输出优化前后对比图。
- 对低置信约束不自动应用，只进入待确认列表。

验收标准：

- 相邻 segment 接缝处双线明显减少。
- 货架宽度和通道宽度更稳定。
- 错误匹配不会无提示地破坏全局地图。

### 阶段 4：结构线和矢量地图

目标：从栅格地图生成业务可用的矢量平面图。

任务：

- 提取墙体和货架边线。
- 合并共线和平行线段。
- 生成货架多边形、通道区域和外围边界。
- 输出 GeoJSON。
- 将价签吸附到最近货架结构。

验收标准：

- 主要货架和通道可以在矢量图中表达。
- 价签与货架关联具备置信度。
- 输出可被后台系统或人工标注工具加载。

### 阶段 5：人工校正和可复现生成

目标：支持真实大型超市交付。

任务：

- 提供校正工具或内部编辑界面。
- 支持点对点、线对线、segment 平移旋转、删除动态障碍。
- 保存 `corrections.json`。
- 重新运行后处理时应用校正。
- 输出完整质量报告和最终地图包。

验收标准：

- 人工只需少量操作即可修正大部分自动歧义。
- 同一输入数据和同一校正文件能生成一致结果。
- 地图包可归档、复查和版本管理。

## 参数建议

初始参数可以按以下方向设置，后续根据真机数据调优。

```text
栅格分辨率：0.05 m
预览分辨率：0.10 m
主结构高度范围：0.30 m 到 2.20 m
地面高度范围：-0.20 m 到 0.20 m
动态小物体最小面积过滤：0.20 m2
价签吸附最大距离：1.00 m
段间自动匹配最小重叠面积：10 m2
段间约束最大允许旋转修正：10 deg
段间约束最大允许平移修正：3 m
冲突栅格告警比例：> 5%
```

这些参数应保存在每次生成结果的 `map.json` 中，不能只存在代码或工具命令里。

## 数据版本和可追溯性

地图生成结果必须能追溯到原始扫描数据。

建议 `map.json` 包含：

- 输入 session 名称。
- 使用的 segment 列表和文件 hash。
- merged db 文件 hash。
- 生成工具版本。
- 生成参数。
- 坐标系转换。
- 使用的人工校正文件 hash。
- 输出文件列表。
- 质量评分。

这样后续如果地图出现偏差，可以判断问题来自扫描、合并、参数、人工校正还是后处理算法。

## 与当前 iOS App 的关系

短期内，iOS App 只需要继续负责：

- 稳定采集分段。
- 稳定导出 segment db 和 sidecar。
- 记录价签和扫描位姿。
- 提供合并数据库入口。
- 提供地图生成任务入口或上传入口。

二维地图生成可以先放在离线工具、桌面端或服务器端。等算法稳定后，再考虑把轻量版本集成到 iOS：

- 手机端生成低分辨率预览图。
- 后台生成高质量最终地图。
- 手机端查看质量报告和待确认区域。
- 人工校正可以在平板或桌面端完成。

这种分工能避免在手机端承受大地图点云处理、全局优化和矢量化的内存压力。

## 风险和应对

### 风险：重复货架导致错误配准

应对：

- 不依赖单一 ICP 分数。
- 引入轨迹连续性、价签、人工锚点和结构方向约束。
- 对低置信匹配只提示，不自动应用。

### 风险：动态物体被当成固定结构

应对：

- 使用多帧一致性和多 segment 重复观测提高稳定结构权重。
- 对孤立小障碍降低置信度。
- 提供人工删除动态区域能力。

### 风险：高度过滤错误导致结构缺失

应对：

- 保留多高度层中间结果。
- 在质量报告中显示不同高度层预览。
- 支持按场景调整高度阈值并重跑。

### 风险：段间合并后全局弯曲

应对：

- 使用二维位姿图优化。
- 加入主方向约束和人工锚点。
- 对每段修正量设置上限，避免过度优化。

### 风险：地图看起来平滑但实际错误

应对：

- 不隐藏低置信区域。
- 输出 conflict 图层和质量报告。
- 保留原始轨迹和 segment 彩色叠加图。

## 推荐验收数据集

建议建立 4 类内部测试数据：

1. 小区域单段扫描：验证基础投影和占据图。
2. 小区域多段重叠扫描：验证段间配准。
3. 长通道重复货架扫描：验证错误匹配防护。
4. 大型超市真实扫描：验证性能、质量报告和人工校正流程。

每类数据都应保存：

- 原始 segment。
- 合并 db。
- 生成参数。
- 期望结果图。
- 已知问题说明。
- 人工校正文件。

这样后续算法迭代时可以做回归比较。

## 最终交付形态

一个完整地图交付包应包含：

```text
SupermarketMapPackage/
  source_manifest.json
  map.json
  occupancy_grid.png
  occupancy_grid.yaml
  vector_map.geojson
  semantic_layers.json
  price_tags.geojson
  trajectory.geojson
  corrections.json
  quality_report.json
  preview.png
  review_items.json
```

交付时至少能回答：

- 地图覆盖了多少面积。
- 哪些区域扫描充分，哪些区域未知。
- 哪些地方有段间错位或冲突。
- 哪些价签已经可靠吸附到货架。
- 哪些区域需要人工复查。
- 使用了哪些输入数据和参数生成该地图。

## 总结

当前项目已经解决了大型区域扫描的前置问题：分段保存、外部存储、价签记录和数据库合并。下一阶段的二维地图生成不应简单调用原生地图导出，而应建立独立、可解释、可校正的后处理管线。

推荐路线是：

```text
先做离线二维占据图
  -> 再做质量可视化
  -> 再做段间二维优化
  -> 再做结构线和矢量地图
  -> 最后加入人工校正和交付包
```

这样可以把“地图生成粗糙”和“大型多段合并误差”拆成可验证、可迭代的工程问题，避免一次性追求全自动高精度而失去可控性。
